## 本周值得安装

### [rtk](https://github.com/rtk-ai/rtk)

- 来源：GitHub API
- 摘要：面向开发命令的 CLI 代理，项目称可将常见开发命令传入 LLM 的 token 消耗降低 60-90%；以单个 Rust 二进制形式提供，零依赖。
- 为什么重要：适合高频让 Codex 阅读终端输出、测试日志和 Git 差异的工作流。相比直接把原始、冗长的命令输出交给模型，它针对上下文成本做了处理，有机会降低调用成本并让关键信息更集中。
- 下一步：建议现在试用：在一个日常项目安装后，只挑测试失败或 Git diff 分析这类单一场景运行一周，并对照原始输出确认没有遗漏定位问题所需的信息。
- 成熟度与风险：近期有更新，单二进制和零依赖降低了试用门槛；但其 token 节省效果来自项目声明，应以你的真实命令、模型和排障准确率验证，避免因压缩丢失关键上下文。

## 学习与作品集

### [agent-skills](https://github.com/addyosmani/agent-skills)

- 来源：GitHub Trending
- 摘要：一组面向 AI 编码代理的生产级工程技能，明确覆盖 Codex、Claude Code 和 Cursor 等工具。
- 为什么重要：可将当前依赖临场提示词的编码协作方式，转为可审阅、可版本管理、可迁移的工程约束与工作步骤。把其中适合自身项目的技能改造成仓库内规则，本身也是展示 AI 工程实践能力的作品集素材。
- 下一步：建议本周开始：选一个正在维护的项目，先阅读并引入一个与代码审查、测试或调试最相关的技能；根据实际摩擦改写为项目专用版本，并用一次真实任务检验效果。
- 成熟度与风险：近期有更新，定位清晰且直接覆盖目标代理；风险在于通用技能未必匹配现有技术栈和团队约定，应该小范围采用并保留人工审查，而不是整包启用。

## 值得观察

### [Switchyard](https://github.com/NVIDIA-NeMo/Switchyard)

- 来源：GitHub Trending
- 摘要：为 LLM 应用在模型与提供商之间路由流量，同时保留 OpenAI 和 Anthropic 原生 API 兼容性，用于模型选择、基准测试及成本与性能优化。
- 为什么重要：当 Codex 之外还需要把不同模型用于代码生成、评审、总结或批处理时，它可能提供统一的实验和切换层；相比在每个工具中手工改模型配置，更利于系统化比较质量、延迟和成本。
- 下一步：暂不急于部署：本周记录现有 AI 编码任务中最耗费或最需要模型切换的一类任务，后续只有在确实需要多提供商路由或可重复基准测试时，再用一个非生产工作流验证兼容性。
- 成熟度与风险：近期有更新，但候选信息只表明其能力定位和 API 兼容目标，未足以证明生产可用性。路由层会引入鉴权、日志、隐私和故障链路，需要先在隔离环境评估。
