## 工程实践

### [Mano-P：无云依赖的端侧 GUI Agent 部署](https://github.com/Mininglamp-AI/Mano-P)

- 来源：Hacker News
- 摘要：项目主题是搭建不依赖云服务的端侧 GUI Agent。
- 为什么重要：端侧 GUI 自动化可降低数据离开设备的风险，也减少对外部模型服务可用性和成本的依赖。
- 下一步：在隔离测试机上评估其安装、权限边界、界面操作可审计性和失败恢复机制，再决定是否用于内部自动化。


### [GenClass：10 MB 浏览器内模型捕捉不抛异常的缺陷](https://www.npmjs.com/package/@genclass/runtime)

- 来源：Hacker News
- 摘要：GenClass 宣称提供一个约 10 MB、可在浏览器中运行的模型，用于发现不会抛出异常的 bug。
- 为什么重要：前端质量问题常以静默错误形式出现；小型本地运行时若有效，可作为传统监控和测试之外的补充信号。
- 下一步：在非生产构建中接入并设计带真实缺陷的对照样例，核验检出率、性能开销、误报率及其对用户数据的处理方式。


### [LLM 代码翻译中的类型映射问题](https://www.codemetal.ai/research/apples-to-apples-getting-type-mappings-right-in-llm-based-code-translation)

- 来源：Hacker News
- 摘要：研究主题聚焦 LLM 驱动代码翻译时如何正确处理类型映射。
- 为什么重要：跨语言迁移的主要风险往往不是语法生成，而是空值、数值范围、集合语义和错误模型等类型契约被悄然改变。
- 下一步：为代码翻译流程建立类型映射表，并在迁移验收中加入边界值、空值、序列化和异常语义的契约测试。


### [Qwen Code 更新托管 Agent 连接器与 broker 稳健性](https://github.com/QwenLM/qwen-code/releases/tag/v0.25.2-preview.0)

- 来源：GitHub Release: QwenLM/qwen-code
- 摘要：预览版更新说明包含对 managed-agent 的 connector 与 broker 稳健性修复。
- 为什么重要：多 Agent 或托管 Agent 系统的可靠性瓶颈常在连接、消息转发和恢复路径，而非单次模型调用质量。
- 下一步：使用托管 Agent 时，给连接器和 broker 增加断连重试、幂等请求、超时告警与故障注入测试。

- 来源：GitHub Release: ollama/ollama
- 摘要：Ollama 已支持在命令行中直接以决策模型完成判断、分类和评分任务。

### [学习代码翻译的类型契约验证](https://www.codemetal.ai/research/apples-to-apples-getting-type-mappings-right-in-llm-based-code-translation)

- 来源：Hacker News
- 摘要：该研究讨论 LLM 代码翻译中的类型映射正确性。
- 为什么重要：AI 辅助迁移会扩大跨语言改造速度，但类型系统与运行时语义的差异决定了结果是否可上线。
- 下一步：选择一段小型服务模块，先人工定义源语言与目标语言类型契约，再以属性测试和集成测试验证 AI 生成迁移结果。
