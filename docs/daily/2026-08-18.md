## 工程实践

### [Claude Code v2.1.234 支持指定项目转录目录短名](https://github.com/anthropics/claude-code/releases/tag/v2.1.234)

- 来源：GitHub Release: anthropics/claude-code
- 摘要：该版本新增可选环境变量 CLAUDE_CODE_PROJECT_DIR_NAME，供为每个会话分配独立配置目录的宿主指定较短的项目转录目录名；同时新增 selection:clear 键绑定动作。
- 为什么重要：会话转录和配置目录会形成新的工程数据面，路径命名与隔离方式会影响容器化、多租户和调试环境的可维护性。
- 下一步：在 CI、远程开发或沙箱宿主中明确会话目录的项目命名规则，并检查转录文件的保留期限与访问权限。


### [用 guardrail benchmark 评测 agent 插件边界](https://github.com/couldbeme/holdline)

- 来源：Hacker News
- 摘要：该项目自称是用于 AI agent guardrails 的基准测试，并称其发现了作者自身插件的问题。
- 为什么重要：插件、工具调用和外部指令是 agent 风险暴露面；仅有提示词约束无法证明防护在实际攻击或误用条件下有效。
- 下一步：把工具调用权限、敏感文件访问、命令执行和提示注入场景写成可自动运行的回归用例，作为插件发布门槛。


### [对 agent 生成的 Go 代码运行 deadcode 检查](https://towardsdev.com/how-to-find-and-remove-the-dead-code-your-agent-wrote-752eb1e738d0?sk=283d17fe49cb51c9936d99371e7a9d2a)

- 来源：Hacker News
- 摘要：文章聚焦 AI 写入死代码，并介绍使用 Go 团队的 deadcode 工具进行检查。
- 为什么重要：agent 可能完成表面需求但遗留未被调用的分支、兼容层或冗余实现，增加维护和安全审查成本。
- 下一步：将 deadcode 与测试、静态分析一起接入 Go 项目的 PR 或合并后检查；对新增未引用导出符号建立人工审查规则。


### [探索多智能体协同编码环境](https://forklane.ai)

- 来源：Hacker News
- 摘要：该 Show HN 项目将自身描述为供开发团队和 agent 使用的多人编码环境。
- 为什么重要：多人和多 agent 共同修改代码时，任务分配、改动隔离、冲突处理和审核责任会成为实际交付瓶颈。
- 下一步：在引入协同 agent 前，先定义任务所有者、分支或工作区隔离、变更审核者和冲突升级流程。
