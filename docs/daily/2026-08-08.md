## 工程实践

### [Claude Code v2.1.225 增强额度提示与工作区信任控制](https://github.com/anthropics/claude-code/releases/tag/v2.1.225)

- 来源：GitHub Release: anthropics/claude-code
- 摘要：版本为用量警告增加网关支出上限支持，达到上限时显示额度名称、重置时间和运营方消息；同时为 claude agents 增加工作区信任提示。
- 为什么重要：成本上限和工作区信任是代理进入团队环境后的两类核心控制，分别降低失控支出与不可信代码目录带来的风险。
- 下一步：使用网关的团队应同步核对网关版本与额度策略，并在自动化脚本中验证新增信任提示是否会阻塞无人值守流程。

### [Rippling 公开 AI Spend Console 的建设思路](https://www.rippling.com/blog/introducing-ai-spend-console)

- 来源：Hacker News
- 摘要：Rippling 介绍了其从缺少约束的 AI 支出走向集中控制，并建设 AI Spend Console 的实践。
- 为什么重要：模型调用成本治理正在从账单统计升级为工程平台能力，团队需要把费用归属、预算和使用控制纳入日常运行。
- 下一步：为每个应用或代理建立独立成本标签、预算阈值和负责人，并至少按模型、团队与环境拆分费用。

### [OpenCode v1.18.15 修复消息时序与清理问题](https://github.com/anomalyco/opencode/releases/tag/v1.18.15)

- 来源：GitHub Release: anomalyco/opencode
- 摘要：该版本修复了导入或旧消息 ID 乱序时的时间顺序问题，使回退和分叉按真实消息时间执行，并改进截断后的陈旧文件清理。
- 为什么重要：代理会话的顺序错误会影响回退、分叉和上下文重放结果，是可能导致隐蔽行为偏差的数据一致性问题。
- 下一步：依赖 OpenCode 历史会话、回退或分叉功能的用户应升级后复测旧会话导入，并检查截断流程是否仍残留文件。
