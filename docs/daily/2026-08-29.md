### [AI Agent 的责任边界开始被正式框架化](https://learn.microsoft.com/en-us/azure/security/fundamentals/shared-responsibility-ai-agent)

- 来源：Hacker News
- 摘要：Microsoft 发布 AI Agent Shared Responsibility Model，用于说明 AI Agent 场景下不同参与方的安全责任。
- 为什么重要：Agent 落地不再只是模型调用问题，身份、工具、数据、运行环境和业务方之间的责任划分会影响上线与审计。
- 下一步：为现有 Agent 绘制责任矩阵，至少明确模型、Agent 框架、工具服务、数据持有方和业务团队各自负责的安全控制。

## 工程实践

### [LaneGate：用 Git worktree 编排 AI Agent](https://github.com/sudheerdvn/lanegate)

- 来源：Hacker News
- 摘要：LaneGate 是面向 AI Agent 的 Git-native worktree orchestrator。
- 为什么重要：多个 Agent 并行修改代码时，隔离工作目录和 Git 状态有助于降低分支互相覆盖与上下文污染的风险。
- 下一步：为并行编码任务试运行 worktree 隔离；将任务、分支、测试结果和合并状态绑定记录。


### [Agent Harness 应成为工程系统的一等对象](https://www.roderick.dev/writing/2026-08-28-obsessing-harnesses/)

- 来源：Hacker News
- 摘要：文章讨论围绕 AI Agent harness 的工程实践与关注点。
- 为什么重要：Agent 的实际表现不仅取决于模型，也取决于工具、上下文、执行循环和失败恢复等外部控制结构。
- 下一步：评估现有 Agent 时单独记录工具调用成功率、失败恢复、上下文管理和人工介入点，不要只看最终回答质量。


### [AI 生成报告的引用需要独立验证](https://www.stipple.sh/resources/ai-citation-hallucination-benchmark)

- 来源：Hacker News
- 摘要：该条目报告 AI-written reports 中存在引用并不存在的问题，并提供引用幻觉基准。
- 为什么重要：研究、投研和决策报告如果包含虚构引用，会使格式完整但内容错误的输出进入业务流程。
- 下一步：在报告生成流程中增加引用存在性、来源可访问性和主张与原文对应关系检查；把引用验证纳入验收指标。


### [LangChain 预览 MCP 一方适配器](https://github.com/langchain-ai/langchain/releases/tag/langchain%3D%3D1.4.0a2)

- 来源：GitHub Release: langchain-ai/langchain
- 摘要：langchain==1.4.0a2 提供 langchain.mcp alpha preview，可将 MCP server 转换为可交给 create_agent 的 LangChain tools；连接处理使用 FastMCP client。
