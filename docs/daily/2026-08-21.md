- 下一步：在团队代理任务中接入会话列表和实时状态检查，先建立运行中任务、异常任务和已结束任务的基础观测。

### [Ollama 缓存模型元数据，首 token 延迟显著下降](https://github.com/ollama/ollama/releases/tag/v0.32.15)

- 来源：GitHub Release: ollama/ollama
- 摘要：Ollama v0.32.15 在请求之间缓存已解析的模型元数据；发布说明中的基准显示 TTFT 从约 995 ms 降至约 524 ms，同时加入首次启动的桌面引导流程并修复中途卡死问题。
- 为什么重要：本地模型应用的交互体验不仅取决于模型推理速度，也取决于请求准备阶段和异常恢复能力。
- 下一步：升级测试环境后重新测量本地模型的 TTFT 和中途恢复情况，并将请求准备耗时纳入性能监控。


## 工程实践

### [让代码审查循环解释为何无法收敛](https://github.com/QwenLM/qwen-code/releases/tag/v0.21.14-nightly.20260821.9f2342d323)

- 来源：GitHub Release: QwenLM/qwen-code
- 摘要：Qwen Code nightly 版本增加 review 功能：当审查循环未能收敛时，向作者说明原因。
- 为什么重要：代理审查失败如果只有“未通过”结果，开发者无法判断是代码问题、规则冲突还是流程本身无法收敛。
- 下一步：在自动审查流程中保留未收敛原因，并将其作为后续提示、人工介入或停止循环的依据。


### [用端到端 smoke 测试验证代理环境修复](https://github.com/QwenLM/qwen-code/releases/tag/dsw-eas-tb-smoke-20260820-r2)

- 来源：GitHub Release: QwenLM/qwen-code
- 摘要：Qwen Code 发布记录显示，在修复 Harbor adapter cache-gate 后执行端到端回归 smoke，依次运行 1 个 SWE-bench Verified case 和 1 个 Terminal-Bench 2.0 case，结果为 SUCCEEDED。
- 为什么重要：代理基础设施的缓存、沙箱和适配器修复可能影响完整执行链路，单元测试不足以覆盖这类回归。
- 下一步：在环境或适配器修复后，至少串行执行代表性的代码修复任务和终端任务，并记录数据集、状态与运行环境。


### [在全新 Sandbox bootstrap 后重复验证执行链路](https://github.com/QwenLM/qwen-code/releases/tag/dsw-eas-tb-smoke-20260820-r1)

- 来源：GitHub Release: QwenLM/qwen-code
- 摘要：Qwen Code 发布记录显示，在修复全新 Sandbox bootstrap 后执行 SWE-bench Verified 与 Terminal-Bench 2.0 各 1 个案例的端到端 smoke，SWE-bench Verified 状态为 SUCCEEDED。
- 为什么重要：全新环境初始化是代理系统常见的脆弱环节，必须验证从启动、依赖准备到任务执行的完整路径。
- 下一步：把 fresh bootstrap 场景加入发布前回归矩阵，不只验证已有缓存或已初始化环境。


### [为本地推理服务建立首 token 延迟基线](https://github.com/ollama/ollama/releases/tag/v0.32.15)

- 来源：GitHub Release: ollama/ollama
- 摘要：Ollama 发布说明给出了缓存模型元数据前后的 TTFT 基准，约从 995 ms 降至 524 ms。
- 为什么重要：具体的 TTFT 基准可以帮助团队识别模型加载、元数据解析和实际生成之间的性能瓶颈。
- 下一步：对常用模型分别记录冷启动和连续请求的 TTFT，升级后比较结果，并将基准固定到性能回归测试中。
