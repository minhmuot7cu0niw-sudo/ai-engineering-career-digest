# 个人工具与项目侦察周报设计

## 目标
每周从 GitHub 发现并推送最多 3 个对用户实际有用的开源项目。它不是热门榜复刻，项目不局限于 AI，优先覆盖 Codex 使用、开发效率、个人工作流、AI 工程学习和职业作品集。

## 筛选规则
- 硬条件：最近 90 天内有 `pushed_at` 更新，或有近期 Release；仓库公开且可访问。
- 默认门槛：至少 5,000 Stars。
- 例外：低于门槛但与用户当前方向高度匹配的项目可以入选，并在摘要中标注为高匹配新项目。
- 来源：GitHub Search API 为主；GitHub Trending weekly 页面作为补充发现源。
- 排序：实际适配度、维护活跃度、可运行性和学习价值优先于单纯 Stars。
- 去重：此前侦察周报已经推荐过的项目不再短期重复。

## 输出
周日北京时间 09:00 生成中文长图，并通过现有飞书图片推送和 GitHub Pages 独立归档。栏目为“本周值得安装”“学习与作品集”“值得观察”，每栏最多一个项目；没有合格候选时允许留空。每个项目必须说明：项目是什么、解决什么问题、比用户现有方法好在哪里、是否现在值得试、第一步动作、维护成熟度。正文不堆叠超链接，原始地址保留在归档数据中。

## 降级与安全
- GitHub API 无 Token 时使用低频匿名请求；请求失败时保留 Trending 或静态候选，不伪造星标和活跃度。
- 模型不可用时生成明确标注的降级报告，不能把未验证项目包装成推荐。
- GitHub Token 只通过 Actions Secret 注入，不写入仓库。

## 验证
- 单元测试覆盖 GitHub API 响应解析、90 天活跃过滤、候选去重和周报提示词约束。
- 运行现有 Python 测试、语法检查和 GitHub Actions。
