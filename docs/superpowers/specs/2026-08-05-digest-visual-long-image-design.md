# AI 工程与职业速报视觉长图改造设计

- 日期：2026-08-05
- 项目：Project-023-AI工程与职业速报
- 状态：设计已获用户确认，等待规格复核后进入实施计划

## 1. 目标

把现有“Markdown/HTML 文档 + 飞书链接”的日报，改造成一份可直接阅读的移动端长图，并在 GitHub Pages 保留同内容的响应式网页归档。飞书消息的主阅读对象是 PNG 长图；正文不使用文章标题超链接，原始来源只以编号和来源类别呈现。

## 2. 已确认的视觉决策

- 底层纹理采用 C 方案：接近白色的浅底，加低对比度坐标点阵。
- 点阵只提供轻微的工程感，不使用整块纯蓝、纯绿或模板式暖白纸张背景。
- 版式采用“AI / Engineering / Daily”小型元信息、主标题、今日总判断、栏目分段和行动框的结构。
- 不显示没有真实来源的“第 N 期”；不在顶部仿照参考图放置时间。日期只作为文件名、归档元数据或底部低干扰信息存在。
- 视觉参考的是“可读的编辑型速报”，不复制用户提供模板的具体标题位置、期号、时间、底色或内容。

## 3. 内容结构

每日长图控制在约 5 分钟读完，栏目固定为：

1. 今日总判断：用一段话说明当天最重要的工程与职业判断，并列出 2-3 个信号。
2. 关键变化：2-3 条高影响模型、平台、政策或公司动作。
3. 工程实践：3-4 条 Codex、Agent、MCP、RAG、推理部署、AI 编程工具或重要开源项目。
4. 学习优先级：1-2 条论文或技术文章，说明值得学什么、当前是否需要学，以及一项练习。
5. 职业信号：0-2 条影响软件、AI、金融科技岗位技能要求或企业落地的变化。

每条正文必须包含三个可见层次：

- 发生了什么：事实摘要，避免只复述标题。
- 为什么重要：对工程、学习或职业判断的实际影响。
- 你现在做什么：一个可执行、可验证的下一步动作。

每条内容保留来源编号，例如 [1]，并在归档页底部生成编号来源索引。长图正文不展示外部 URL，不让链接成为主阅读路径。

## 4. 页面与长图形态

- HTML 归档和 PNG 长图使用同一个内容模型，避免两套文案漂移。
- 移动端优先，正文宽度稳定，长标题自动换行，行动框不改变布局高度逻辑。
- 主色保持中性深色，蓝色只用于结构线、编号和行动提示；点阵透明度足够低，不能影响文字识别。
- GitHub Pages 继续提供日期归档、首页和 RSS；PNG 与 HTML 使用同一日期路径。
- 飞书图片消息直接展示 PNG；消息文字只保留一句简短说明和归档页入口作为辅助。

## 5. 技术方案

### 5.1 生成链路

1. digest.py 抓取并去重 RSS、GitHub Releases、Hacker News 和 ArXiv。
2. 模型返回结构化 JSON，包含 overview、sections、items、summary、why、action 和 source_index。
3. 渲染器生成 Markdown、响应式 HTML 和日期 PNG。
4. PNG 写入 docs/daily/YYYY-MM-DD.png；HTML 写入 docs/daily/YYYY-MM-DD.html；JSON 和 RSS 保持现有归档结构。
5. GitHub Actions 提交 docs 并部署 GitHub Pages。

### 5.2 PNG 渲染

采用无头 Chromium 截取与归档 HTML 同源的页面，保证中文字体、换行、点阵纹理和行动框与 Pages 一致。渲染脚本独立于模型调用，允许本地通过固定 JSON fixture 重复生成截图并检查非空尺寸。

### 5.3 飞书推送

现有自定义机器人 Webhook 继续作为文本兜底。要实现真正的图片消息，需要增加飞书自建应用能力：

- 应用凭证：FEISHU_APP_ID、FEISHU_APP_SECRET
- 目标群聊：FEISHU_CHAT_ID
- 运行时先获取 tenant access token，再上传 PNG，最后发送 image message。

当图片推送配置完整时，飞书发送 PNG；配置缺失或上传失败时，不伪装成成功，改发 Webhook 文本兜底，并包含 Pages 归档链接和失败原因摘要。

### 5.4 工作流

每日和每周工作流增加 Node/Chromium 渲染依赖安装与图片推送所需环境变量。模型调用失败时仍生成降级版 HTML/PNG；图片推送失败不影响 Pages 归档提交，但工作流日志必须明确标记降级原因。

## 6. 错误处理

- 模型不可用：使用现有 fallback sections，标记 degraded=true，照常生成归档与 PNG。
- 浏览器渲染失败：保留 HTML/JSON，发送 Webhook 错误通知；工作流失败，禁止发送“图片已成功推送”的假消息。
- 飞书应用凭证缺失：页面照常发布，Webhook 说明需要完成应用配置。
- 任何原文 URL 只保留在 JSON、RSS 和归档索引，不插入长图正文标题。

## 7. 测试与验收

- 单元测试覆盖结构化模型解析、内容三层字段、长图 HTML 的点阵 CSS、日期文件路径和无外链正文。
- 渲染 smoke test 验证 PNG 存在、宽度固定、文件大小大于 0、关键栏目文字存在。
- XML RSS 验证继续保留。
- 在桌面和移动宽度各检查一次：标题不溢出、行动框不遮挡正文、点阵不压过文字、长图可完整滚动。
- 验收标准：飞书能直接显示一张长图；用户无需点击文章链接即可读完核心判断和下一步动作；GitHub Pages 可打开同款 HTML 与 PNG。

## 8. 不在本轮范围

- 复杂背景插画、品牌 Logo 或动态动画。
- 招聘网站批量抓取。
- 改变现有信息源范围和周报频率。
- 让飞书图片消息承担完整来源浏览；完整来源仍留在归档页。
